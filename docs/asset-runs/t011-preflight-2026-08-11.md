## 완료 evidence와 연락표 준비 상태

완료 validator는 현재 manifest SHA-256과 redacted provider ledger SHA-256, 실제 call mode, 정확히 4개의
candidate/invocation/provider-result 1:1 기록을 요구합니다. ledger의 각 실제 호출에는 tool, model,
`use_unlim=false`, canonical request SHA, provider result ID, 제출·완료 관찰 시각과 호출 전후 balance
checkpoint가 있어야 합니다. 전체와 호출별 decimal 차감도 각각 6.00과 1.50으로 맞아야 합니다.
manifest와 정확히 같은 local/backup 상대경로, 동일한 64자리 SHA-256과 3:4 PNG
회수·양쪽 검증 필드를 요구합니다. signed URL, token, account, email, session, raw error 필드나 민감해
보이는 값은 거부합니다. 정적 HTML 연락표는 이 완료 evidence를 통과한 경우에만 local public asset
경로를 사용해 생성됩니다. 완료 evidence를 위조하거나 대신하는 명령은 없습니다.

```bash
npm run assets:style:gen
npm run assets:style:check
npm run assets:style:contact-sheet -- \
  --evidence <repository-relative-evidence.json> \
  --provider-ledger <repository-relative-redacted-ledger.json> \
  --output docs/asset-runs/contact-sheets/<safe-name>.html \
  --local-root <local-public-assets-root> \
  --backup-root <distinct-backup-root>
```

연락표는 evidence의 메타데이터만 신뢰하지 않습니다. local과 별도 backup root의 실제 PNG를 각각 다시
열어 SHA-256, byte size, 3:4 aspect와 width/height를 evidence와 대조합니다. 두 root는 겹칠 수 없고,
출력은 위 전용 디렉터리만 허용하며 같은 byte에는 idempotent, 다른 byte에는 no-clobber입니다. 현재
HOLD에서는 evidence를 읽기 전에 명령이 차단되므로 `gen`과 `check`만 준비·검증 용도로 사용합니다.
`style-candidates-v1`은 구조적으로 HOLD-only라 gate나 evidence를 바꿔 READY로 만들 수 없습니다.
향후 `generate_image_batch`나 연락표를 허용하려면 실제 batch limit과 candidate/job topology를 검증하는
새 manifest version·validator와 재승인이 필요합니다. 실제 완료 evidence와 연락표는 생성하지 않았습니다.
